# Parichayam Admin Training Checklist

Use this as the practical handover sheet for a new admin or business operator.

## 1. Access and Readiness

- [ ] Confirm access to the live admin panel.
- [ ] Confirm access to the member dashboard for testing.
- [ ] Confirm access to Firebase Console for emergency checks.
- [ ] Confirm access to payment gateway dashboard.
- [ ] Confirm access to MSG91 OTP dashboard.
- [ ] Confirm access to official support email and support phone.
- [ ] Confirm who owns verification, payments, content, and agent payouts.

## 2. Website Basics

- [ ] Open the index page and confirm all main buttons work.
- [ ] Open the auth page and confirm login, signup, and forgot password are visible.
- [ ] Confirm registration can start from the public website without errors.
- [ ] Confirm at least one test user can sign in successfully.

## 3. Registration and Trial Flow

- [ ] Verify registration step 1 captures profile-for, name, mobile, email, and password.
- [ ] Verify OTP is required if OTP mode is enabled.
- [ ] Verify trial signup works when the user does not choose a paid plan.
- [ ] Verify paid-plan signup redirects to checkout.
- [ ] Confirm new users get a member account after successful registration.

## 4. Profile Quality Training

- [ ] Explain why age, city, community, gotra, education, profession, income, and about section matter.
- [ ] Explain why photos improve response rate.
- [ ] Explain why jathakam fields matter for traditional families.
- [ ] Explain why Aadhaar and income verification improve trust.
- [ ] Train admin to identify incomplete or low-quality profiles.

## 5. Matchmaking Training

- [ ] Admin understands that only opposite-gender profiles should appear in normal suggestions.
- [ ] Admin understands same-gotra can be blocked if policy is hard.
- [ ] Admin understands age fit is directional, not just absolute.
- [ ] Admin understands city/state/community affect match ranking.
- [ ] Admin understands verification, completeness, and recent activity improve ranking.
- [ ] Admin understands boost is a visibility bonus, not a full override of relevance.

## 6. Admin Panel Training

### Pricing and Revenue
- [ ] Change a membership price and verify the save flow.
- [ ] Review add-on prices and understand each revenue stream.
- [ ] Review connect pack settings and how connect credit requests are handled.

### Dashboard Builder
- [ ] Show how to enable or disable a member dashboard section.
- [ ] Explain which sections are CORE and cannot be hidden.
- [ ] Verify members see the change on next load.

### Profile Form Builder
- [ ] Show how to mark a field as shown or hidden.
- [ ] Show how to mark a field as required.
- [ ] Explain that hiding too many important fields lowers match quality.

### Community and Gotra Management
- [ ] Add a sample community.
- [ ] Add a sample gotra.
- [ ] Explain why clean spelling and standard values matter.

### Verification Queue
- [ ] Review one Aadhaar verification request.
- [ ] Review one income verification request.
- [ ] Approve and reject examples using test data.

### User Access Control
- [ ] Show how to activate an add-on for a user.
- [ ] Show how to suspend or restrict a user if needed.
- [ ] Explain when to hide, suspend, or block a profile.

### Agents and Franchise
- [ ] Review agent application list.
- [ ] Review agent creation process.
- [ ] Review payout approval and rejection process.
- [ ] Explain how agent referrals connect to member acquisition.

## 7. Daily Operations Checklist

### Morning
- [ ] Check new registrations.
- [ ] Check trial expiry watchlist.
- [ ] Check verification queue.
- [ ] Check payment success and failure issues.
- [ ] Check agent applications and payout requests.

### Afternoon
- [ ] Spot-check at least 3 member dashboards for match quality.
- [ ] Review incomplete profiles that need follow-up.
- [ ] Review support complaints from phone, WhatsApp, or email.

### End of Day
- [ ] Check revenue summary.
- [ ] Confirm no major admin setting was changed without validation.
- [ ] Confirm no serious profile or verification backlog remains.

## 8. Common Mistakes to Avoid

- [ ] Do not approve weak or fake profiles just to increase counts.
- [ ] Do not hide critical fields like city, education, profession, or community without reason.
- [ ] Do not change OTP or payment settings without testing signup and checkout.
- [ ] Do not enable strict same-gotra blocking unless gotra data quality is clean.
- [ ] Do not over-promise that every partner preference is fully enforced by the current system.

## 9. Escalation Rules

- [ ] OTP or login failure -> check auth settings and OTP provider first.
- [ ] Payment failure -> check payment settings and backend verification flow.
- [ ] Sudden drop in matches -> check same-gotra policy, profile visibility, and data quality.
- [ ] Low-quality matches -> review missing fields, community or gotra cleanliness, and verification backlog.
- [ ] Agent complaints -> review referral records, commissions, and payout requests.

## 10. Sign-Off

- [ ] Admin has completed live walkthrough.
- [ ] Admin has completed one test registration.
- [ ] Admin has reviewed one verification request.
- [ ] Admin has changed one safe dashboard setting and verified the result.
- [ ] Admin understands daily, weekly, and escalation responsibilities.
